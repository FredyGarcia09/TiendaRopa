1. INTRODUCCIÓN Y CONTEXTO DEL PROYECTO
================================================================================
El presente documento describe los cambios técnicos y funcionales implementados en el sistema web para la gestión y punto de venta de una Tienda de Ropa desarrollado sobre el framework Django. En este avance de proyecto (AV1), se aborda de forma específica la problemática de la administración y control de existencias de inventario por producto y por variante de color.

El modelo de datos del sistema vincula a cada prenda o producto general (modelo Ropa: descripción, marca y proveedor) con sus variantes de inventario físico (modelo Modelo: talla, color, precio y stock actual). El objetivo de este entregable consiste en permitir al encargado de tienda consultar el inventario global de cada prenda y, a su vez, disponer de una interfaz amigable e intuitiva para consultar y actualizar el inventario individual correspondiente a cada uno de sus colores disponibles.

================================================================================
2. REQUERIMIENTOS SOLICITADOS Y CUMPLIMIENTO
================================================================================
A continuación se resume cómo se dio cumplimiento exacto a los requisitos solicitados por la docente:

1. Lista general de productos con información básica e inventario total disponible:
Se diseñó e implementó una vista basada en clases que lista todos los productos registrados, mostrando su identificador, prenda/descripción, marca, proveedor, colores disponibles y el total de inventario disponible (calculado automáticamente mediante la suma de existencias de todos sus colores y tallas).

2. Botón de acceso al inventario por producto:
En cada fila de la lista de productos se integró un botón de acción rotulado como "Inventario" que redirige al usuario al formulario específico de gestión de existencias de la prenda seleccionada.

3. Formulario para consultar y actualizar el inventario por color:
Se construyó una vista y plantilla dedicada que muestra la información de cabecera del producto seleccionado y un formulario tabular interactivo con cada uno de los colores y modelos disponibles, permitiendo ingresar los valores actualizados de inventario y almacenarlos de forma persistente en la base de datos al presionar el botón de guardado.

4. Integración de DataTables y respeto a los estilos Bootstrap 5:
Todas las tablas del módulo hacen uso de la librería DataTables con el adaptador oficial de Bootstrap 5, manteniendo los iconos organizados exclusivamente en los encabezados, diseño limpio en las celdas, paginación, búsqueda instantánea en español y adaptabilidad responsiva sin sobrecargar la interfaz.

5. Navegación fluida y consistente en el menú:
Se integró el nuevo módulo en la barra de navegación superior (pestaña "Inventario" y menú desplegable "Catálogos") y se habilitó la tarjeta correspondiente en el menú principal (Home) para asegurar una navegación directa y accesible entre todas las vistas.

3. ARQUITECTURA Y MODIFICACIONES TÉCNICAS
================================================================================

3.1. Configuración de Rutas de Navegación (gestion/urls.py)
Se incorporaron dos rutas fundamentales: una para la lista general de inventario ('inventario/') y otra parametrizada con el identificador del producto para consultar y actualizar sus colores ('inventario/<int:ropa_id>/').

[CÓDIGO: gestion/urls.py]
from django.urls import path
from . import views

urlpatterns = [
    path('', views.HomeView.as_view(), name='home'),
    path('home/', views.HomeView.as_view(), name='home_alt'),
    path('ropa/', views.RopaListView.as_view(), name='ropa'),
    path('inventario/', views.InventarioListView.as_view(), name='inventario_lista'),
    path('inventario/<int:ropa_id>/', views.actualizar_inventario_view, name='actualizar_inventario'),
]

3.2. Lógica de Negocio y Controladores (gestion/views.py)
Se definieron dos componentes principales:
- InventarioListView: Hereda de generic.ListView. Optimiza el acceso a la base de datos mediante select_related('proveedor') y prefetch_related('modelo_set') para calcular los totales de stock en memoria sin generar consultas redundantes (evitando el problema N+1).
- actualizar_inventario_view: Función controladora que procesa tanto peticiones GET (para renderizar los datos del producto y sus colores) como peticiones POST (para recibir los nuevos valores de stock de cada color, validarlos como enteros no negativos, almacenarlos mediante save(update_fields=['stock']) y emitir un mensaje de confirmación mediante django.contrib.messages).

[CÓDIGO: gestion/views.py]
from django.shortcuts import render, get_object_or_404, redirect
from django.contrib import messages
from django.views import generic
from .models import Ropa, Modelo

class InventarioListView(generic.ListView):
    """Vista general para consultar productos con su inventario total disponible."""
    model = Ropa
    template_name = 'inventario_lista.html'
    context_object_name = 'ropas'

    def get_queryset(self):
        return (
            Ropa.objects.select_related('proveedor')
            .prefetch_related('modelo_set')
            .all()
            .order_by('id')
        )

def actualizar_inventario_view(request, ropa_id):
    """Formulario para consultar y actualizar el inventario existente de un producto por color."""
    ropa = get_object_or_404(
        Ropa.objects.select_related('proveedor').prefetch_related('modelo_set'),
        pk=ropa_id
    )
    modelos = ropa.modelo_set.all().order_by('color', 'talla')

    if request.method == 'POST':
        for modelo in modelos:
            campo = f'stock_{modelo.id}'
            if campo in request.POST:
                try:
                    nuevo_stock = int(request.POST[campo])
                    if nuevo_stock >= 0:
                        modelo.stock = nuevo_stock
                        modelo.save(update_fields=['stock'])
                except ValueError:
                    pass
        messages.success(request, f'Inventario actualizado con éxito para "{ropa.descripcion or ropa.marca}".')
        return redirect('actualizar_inventario', ropa_id=ropa.id)

    total_stock = sum(m.stock for m in modelos)
    return render(request, 'inventario_detalle.html', {
        'ropa': ropa,
        'modelos': modelos,
        'total_stock': total_stock,
    })

5. CONCLUSIÓN
================================================================================
La solución desarrollada satisface a cabalidad las especificaciones requeridas para el Avance 1. Se implementó una arquitectura modular en Django aprovechando vistas basadas en clases para las consultas generales y vistas funcionales optimizadas para el procesamiento transaccional de formularios múltiples.

La separación de responsabilidades entre el modelo general de la prenda (Ropa) y sus existencias por color y talla (Modelo) permite un control granular de inventario esencial para cualquier punto de venta textil, mientras que el uso de DataTables y Bootstrap 5 garantiza una experiencia de usuario rápida, responsiva y profesional.
